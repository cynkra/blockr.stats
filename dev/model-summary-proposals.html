Visual model summaries

Fourteen ways to show a fitted model in a dashboard, from a bare coefficient plot to a full summary card. The question underneath: how many blocks is this, and where is the cut between "the coefficients" and "the model"?

Every variant is drawn from real output of three models, so the shapes are honest about how much room the numbers need: lm(body_mass_g ~ flipper_length_mm + species) on penguins (n = 342) and coxph(Surv(time, status) ~ sex + age + ph.ecog) on lung (n = 227, 164 events). Each caption names the broom verb that feeds it, which is the constraint that keeps one implementation working for lm, glm, coxph and survfit alike.

Part 6 · The summary block

The decision: the model block keeps the fitted object and prints it, nothing more. Everything visual moves into a second block downstream, Model summary, which takes the model object and renders the card. The rest of this section is what that card looks like and what its gear holds.

Six controls, no face controls: the block's face is the card itself. Three selects and three switches is about the ceiling for a gear, so the list below is as much about what stays out.

Settled: the default rendering is V15 as drawn, intercept row included. V15a is not a second default, it is the state you reach by turning the effect column off and switching significance to chips. Sort order is not an option at all, see below.

What each option is for

OptionValues (default first)Why it earns a slot
Uncertainty 95% CI · 90% · 99% · ± standard error · none The one you asked for. It drives the whisker and the text column together, so the two can never disagree. Note these are different things: a CI is a range you would bet on, ± SE is one standard error either side (about 68%), so the column header has to name which is drawn. "None" gives a bare estimate column for a slide.
Significance p-value column · chips (0.1% / 1% / 5%) · stars · off Three audiences, one number. The p column is for the analyst, the chip is the seasonal.website reading for the dashboard, stars are what a paper wants. Off matters more than it sounds: with a CI drawn, significance is already visible as "does the whisker cross zero", and some teams deliberately do not want a threshold rendered at all.
Coefficient scale Auto · raw (link scale) · ratio (exponentiated) A logistic or Cox coefficient is unreadable on the log scale and misleading if you exponentiate silently. Auto means ratio for binomial/Poisson/Cox and raw for lm; the override exists because someone always wants the log coefficient. Changing it also flips the reference line from 0 to 1 and the axis to log.
Effect column on / off Off turns the card into a plain numeric table, which is what you want when the block sits beside a chart that already carries the picture, or when the panel is narrow. The column is the first thing to lose.
Model facts line on / off Off when the fit is reported elsewhere on the page, or when the audience should not be reading R² at all. Which facts appear is per model class and not a user choice: adj. R² and residual SD for lm, concordance and events for Cox.
Intercept row on / off On by default: the summary should show the model that was fitted, and a table that silently drops a row it computed is a table you cannot check against summary(). The usual argument for hiding it, that it wrecks the shared scale, is answered by the off-scale arrow rather than by deletion, since the intercept never enters the plot's scale. Off for the presentation case where only the offsets are the story.

What I would keep out of the gear

Not an optionBecause
Sort terms Cut. A coefficient table is read against the formula that produced it, so model order is the only order that lets you check one against the other. Reordering by size or by p is a reading aid for one wide model that costs a permanent gear slot on every narrow one, and it quietly turns the table into a ranking, which invites reading the top row as the most important variable when the terms are on different scales.
Decimal places Auto-format from the magnitude of the column, the way the table block already does. A digits spinner is a request to make it worse.
Term labels Splitting speciesGentoo into "species Gentoo" and using column labels where the data has them should always happen. Nobody prefers the raw name.
Which glance columns A column picker over glance is a second block (V14 comparison) pretending to be an option. Per-class defaults, no picker.
Colours / reference line Design-system decisions. If the sign colours are wrong they are wrong for everyone.
R print pane Lives in the model block now. Two blocks showing the same text is a bug, not a feature.
Diagnostic tests The Shapiro / Breusch-Pagan line from V7 is a different job with its own assumptions. If it happens, it is a diagnostics block, not a checkbox here.

One case the block has to survive: a Kaplan-Meier fit. tidy(survfit) returns curve points, not coefficients, so there is no coefficient table to draw. The card should degrade to the facts line (n, events, median survival) and say the model has no coefficients, rather than render a thousand-row table of time points.

Where the block boundary goes

Decided, with the alternatives recorded.

OptionBlocksTrade
B. Two blocks ✓ Model block returns the fitted object, preview is the R print, no visual and no options. Model summary block sits downstream, takes the object, renders V15 and holds the gear. The model block goes back to doing one thing. The card is placeable, exportable and configurable without touching the fit. Costs one block in the menu and one link to draw, which is the normal blockr gesture.
A. One card Model block preview shows the card, with the R text behind a toggle. Zero wiring, one screen. Rejected: fit and options get tangled into the block that does the fitting, and you cannot put the summary in a different panel from the model.
C. Renderer, not block Broom adapter stays the only stats block; the card becomes a table/chart preset over a tidy frame. Nothing new in blockr.stats and reusable for any tidy frame. Rejected: a three-block chain to see your coefficients, and glance and tidy cannot be combined in one frame, so the facts line would need a second chain.

The broom constraint is what makes the summary block portable: it needs tidy(conf.int = TRUE) and glance() and nothing else, so one implementation covers lm, glm, coxph, aov and anything else with a broom method. The broom adapter block stays for the people who want the frame itself.

Colour: estimates use one diverging pair, #2563eb above the null and #dc3545 below, with grey #9ca3af where the interval covers the null. The pair passes the six-check validator on a light surface (CVD ΔE 26.2 protan, normal-vision ΔE 36.1, contrast ≥ 3:1); the grey is below the contrast floor by design and is therefore never the only cue, every row carries its value as text. The species lines in V13 use the Okabe-Ito steps blockr.theme ships. Light surface only, matching the product; these are static mockups, so hover and tooltips are not wired.
