The model summary line, and what a column header looks like

Two open questions on the shipped model summary card: the one-line model summary above the table, and whether the column names should follow the blockr column header instead of the micro-caps the card invented.

Every mock below uses the real CSS: the card styles are copied verbatim from R/css.R, the column header from blockr.ui/inst/assets/css/blockr-table-preview.css and blockr.viz/inst/css/table.css, and the tokens from the target set in blockr.docs/design-system/target/design-system.html. Numbers are a real penguins fit: body_mass_g ~ flipper_length_mm + species, 333 observations.

Part 1 · The column header

This one I think is simply a bug in what I shipped. blockr has a column header, in two places that already agree with each other, and the card ignored it.

The recipe, verbatim: 14px medium in primary ink for the name, an 11px normal muted .blockr-col-label underneath, numeric columns right-aligned (viz drives that off the column type). The card stops inventing and starts matching the preview and the table block. The sub-label earns its keep here: "Effect / 95% CI" says what the whisker is without spending a parenthesis, and "Estimate / body mass (g)" is the one place the response's units can appear at all. Costs one line of header height.

Sorted descending by estimate (hover a header to see the hint arrow; the unsorted arrow reserves no width, so nothing shifts). Note the intercept stays pinned last in every sort: it is the baseline, not a competitor, and it is out of the shared scale.

Sorting is a decision, not just CSS. We cut "sort terms" as a gear option an hour ago, for a reason that still holds: reordering turns a coefficient table into a ranking across terms measured on different scales. A header click is a weaker, better version of the same thing (no gear slot, no change to the default reading, standard table affordance) — but it has to live somewhere. Purely in JS it is lost on every redraw, and the card redraws on every option change and every upstream refit. Persisted, it is block state, and lands in the saved board and the exported code. My recommendation: ship H2 now, leave H3 for when the sort belongs to the shared table component rather than being reimplemented per card.

Part 2 · The one-line model summary

What ships is S1. The question behind all of these: is this line an identity ("what model is this?"), a scorecard ("how good is it?"), or both — and how much visual weight should something the reader checks once, and then ignores, be allowed to take?

S1

Dot-separated run — ships today

Linear model ·333 obs ·adj. R² 0.785 ·residual SD 373.3 ·AIC 4895

One line, wraps safely, cheap. The complaint: five facts of four different kinds (what it is, how much data, two fit measures, one information criterion) all at the same pitch, so nothing is findable and the eye slides off. Also the only bolded things are numbers whose labels are the quiet part, which is backwards.

S2

Identity left, fit right

Linear model · 333 obs adj. R² 0.785 SD 373.3 AIC 4895

Same height, two jobs separated: what the model is on the left, how well it fits on the right, where numbers belong. Costs nothing, and the right edge lines up with the table's numeric columns.

S3

Stat tiles

Linear model · 333 obs
adj. R²0.785 residual SD373.3 AIC4895

V5 from the first round, kept honest. Findable and scannable, but it is two lines and it out-shouts the coefficients: in a dock panel the fit stats would be the loudest thing on a card whose point is the terms. Right for a card that is only the fit; wrong above a table.

S4

Sentence

Linear model of body mass on 2 predictors, 333 observations, explaining 78.5% of the variance (residual SD 373.3).

Reads without training, and it is the only variant that can say "78.5% of the variance" instead of "R² 0.785". Against: prose does not survive a Cox or a Poisson without a per-class template, it wraps to three lines in a narrow panel, and a reader coming back for the third time has to re-read a sentence to find one number.

S5

Formula first

body_mass_g ~ flipper_length_mm + species Linear model· 333 obs· adj. R² 0.785· SD 373.3· AIC 4895

The formula is what the model is, and right now it appears nowhere on the card — it lives in the block's name, which a reader of an exported report never sees. Monospace, response tinted. Against: a wide formula truncates, and on a board the block title usually says it already.

S6

The column-header vocabulary, reused

Linear model333 observations 0.785adj. R² 373.3residual SD 4895AIC

The same two-tier pattern as the column header: 14px medium value, 11px muted label underneath. Why I like it: if Part 1 lands, the card already speaks this language in its header, so the summary line stops being a fourth kind of typography on one card. Value-over-label also puts the numbers where the eye looks first, and it survives any model class because it is just pairs.

S7

One hero number

0.785adj. R² Linear model · 333 obs
residual SD 373.3 · AIC 4895

Picks the one fit measure that suits the class (adj. R² for lm, concordance for Cox, pseudo-R² for a GLM) and makes it the anchor. Against: it asserts that one number is the headline, which is exactly the habit that gets R² over-read; and for an AIC-only model there is no defensible hero.

Decided

Christoph, 2026-07-26 — implemented. Summary line: S2. Column header: the blockr column header without the sub-label tier (the interval stays inside the name it qualifies, "Effect (95% CI)"), and with sorting. Sorting is pure JS and stores nothing: sort by name, by largest coefficient or by weakest evidence, which is what you want once a model has many predictors. Because the card is redrawn by R on every update, the chosen order is remembered per output in the browser and re-applied to the new table — it lives as long as the tab, never reaches R, and never enters the saved board or the exported code. A third click on the same column returns to model order, and the intercept stays pinned last in every order.

What I had recommended

QuestionRecommendationWhy
Column header H2 — the blockr column header, sub-label carrying the interval and the response units Not really a preference: blockr already has one column header, used by both the preview and the table block, and the card invented a different one. The sub-label tier then pays for itself twice over.
Sortable Not yet Right gesture, wrong owner. A per-card sort is either lost on redraw or becomes block state we deliberately declined. Worth doing when the shared table component owns sorting.
Summary line S6, with S2 as the fallback if the two-tier line feels too tall S6 makes the card speak one typographic language once H2 lands, and reads value-first. S2 is the zero-risk version of the same idea: identity left, numbers right, one line.
The formula (S5) Worth having, but as a gear option rather than a default It is the only thing on the card that says what was fitted, which matters in an exported report where the block title is gone. It also duplicates the block title on a board, which is why it should not be on by default.

Open question I cannot answer from here: the response units ("body mass (g)") in the Estimate sub-label. We can only fill that in when the upstream data carries a column label — real for ADaM/BDS data, absent for penguins and mtcars. So the sub-label has to be optional, and the header must not jump a line when it is missing.
